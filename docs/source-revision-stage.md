# 保持原窗的显式源文修订暂存

`media_workflow.source_revision`将已经完整验证的意群音频暂存与显式源文修订合并到新的隔离工程。它是通用共享适配器，不复制单片生产脚本，不改98个冻结根Python、原片、规范工程、生产缓存或成片。当前只实现`prepare/check`，**不提供旧字幕投影、质量或安装分派桥接**。

```bash
/vol_1t/pyvideotrans/.venv/bin/python -m media_workflow.source_revision prepare CONFIG.json --output NEW_STAGE
/vol_1t/pyvideotrans/.venv/bin/python -m media_workflow.source_revision check CONFIG.json --output NEW_STAGE
```

成功或失败目录均保留；不要重启已经成功的父音频暂存、TTS或媒体。更换来源、编号、时间窗或角色不是本合同支持的操作。

## 输入与证据

配置精确包含六个字段：

| 字段 | 契约 |
| --- | --- |
| `kind` | `preserved-window-source-revision-stage-v1` |
| `work` | 原规范工程绝对路径 |
| `parent_config`、`parent_manifest` | 已成功的`editorial_sample_grid`配置和清单的完整身份 |
| `proposal` | `explicit-source-amendment-proposal-only-v1`的完整身份 |
| `translation_input_before` | 原规范`translation_input.tsv`的完整身份，不猜其仍是当前全文导出 |

父暂存必须通过原检查，保留严格原窗、完整正常试读、增益处理、旧样本所有权及实际原声。源文提案和作者审校必须已经被原完整试读计划绑定，不能事后换成另一个提案。提案另附原始JSON3、旧来源元数据和具体来源证据。

每项修订精确列出编号、原始起止字符串、原全文、修订后全文、非空单一替换、具体依据和证据限制。当前只允许一个唯一词面替换；不允许额外修改、重复替换或用模糊匹配猜位置。提案保持全量编号自身映射、总数和全部时窗不变；不得声称修订后词流守恒或已经人耳确认。

试读计划中的`requires_explicit_source_amendment_before_adoption`在本适配器中受到实际检查：提案编号集合必须与所有已披露编号完全一致，每一项也必须存在于父暂存选择中。不能静默丢掉有困难的年份单元或夹带未披露修订。这个检查只属于本新合同，不冒称旧适配器认识附加字段。

## 暂存结果与严格检查

- 父暂存清单、旧源文、旧任务、旧合成和波形全部不修改。新工程只对选定英文SRT词面作字节局部替换，不统一格式或移动时间；未选319项等保全数量以实际项目验证为准。
- 原始JSON3、旧`source_provenance.json`及旧`translation_input.tsv`精确归档，包含字节数、摘要和mtime；它们是历史证据，不被冒充为修订后当前内容。
- 生成新的全量`source-input.tsv`，重新绑定`translation_task.json.source_sha256`、`source`和显式`source_revision`。新任务指向新、不可变的全文导出；旧规范导出和来源元数据保留为历史，不偷偷覆盖。
- 用已有编译器生成当前中文、朗读、双语字幕与编译绑定。中文、朗读、声音、统计、时窗必须逐字节等于父暂存；双语英文必须对应修订后的源文。
- 编译器会重新生成`normalization_changes.json`。本合同精确要求新的编译输入契约、空朗读变化列表和`production_audio_modified=false`；不能简单要求其旧字节不变，也不能放宽为任意记账。
- 基础和原声复合波形直接复用父暂存身份，不重做增益、不重新合成。实际原声区、占位、严格原窗审计和窗外样本证明仍由原父暂存完整检查。
- 新的来源合同与旁白采用明确新来源和依赖。裸旧stage和旧旁白验证器应拒绝，不删依赖或伪装成旧来源。当前没有将它接到正式媒体的隐藏分派器。
