## 版本化朗读规范

旧工程没有 `speech_policy.json` 时继续使用 legacy；新工程从正式 CLI 第一次 compile 默认使用 technical-v2。显式升级旧工程：

```bash
.venv/bin/python video_workflow.py compile 'YouTube链接' --normalization technical-v2
```

升级会改变编译契约，保存 `speech_policy.json` 和 `normalization_changes.json`，列出受影响单元。旧 WAV 及成品不被覆盖，但不能继续冒充与新朗读稿匹配；之后需按 `tts → render → verify` 生成新修订。不要在尚未听过局部样片时批量升级。显式选择 `--normalization legacy` 可重新编译旧规则，但不会恢复被覆盖的历史阶段清单。

technical-v2 使用 ASCII 标识符边界，能处理 `CPU缓存`，不匹配 `XCPUY`、`CPUs` 或 `CPU_CACHE`。反引号代码、URL、命名空间/点号成员和绝对路径保持原样。`CPU`、`IPC` 等按字母拼读；容量、位/字节、二进制/十进制单位与速率分别展开。例如 `64 KiB` 为“64 二进制千字节”，`64 KB` 为“64 千字节”，`8 Gb` 为“8 吉比特”，`2 GB/s` 为“每秒 2 吉字节”。这是项目朗读规范，不是对所有音色已正确发音的认证；未知缩写保持待核。

显示字幕始终保留正常术语。内置术语发现库仍不注入未经试听的谐音字，不支持任意 SSML 音素控制。

## 局部 A/B，而非直接全片替换

```bash
.venv/bin/python video_workflow.py speech-plan 'YouTube链接'
.venv/bin/python video_workflow.py speech-preview 'YouTube链接' --preview-limit 6
```

`speech-plan` 先补扫当前音频，输出 `speech_polish_plan.json`：

- 跨单元语义组候选：保留来源单元、原文、绝对时间和当前音色；不同音色不合并。同一音色不等于已确认同一讲者，讲者和画面锚点仍需人工确认。
- 朗读规范候选：对比当前朗读和 technical-v2，不改变编译输入。
- 代表性术语探测：每类术语选局部语境，记录目标读法；重新合成探测不等于应用了强制发音规则。

可对照原文编辑计划中的 `proposed_spoken`，不能修改来源、音色或时间字段。编辑后直接执行 `speech-preview`；再次执行 `speech-plan` 会重新生成草案。输入变化使旧计划失效。

`speech-preview` 使用已配置的网络 Edge-TTS，自动切换到 pyVideoTrans Python 环境，单次每工程最多 20 例，每例不超过 40 秒。去重相同来源/音色/文本，输出独立的 `speech_previews/<修订>/index.html`、`manifest.json`、原版剪辑和候选 WAV；不写生产 `tts_cache`、`narration.json` 或主视频。失败保留部分证据，不把未完成结果设为当前样片。

样片保存引擎/音色/文本、原始 MP3、WordBoundary 元数据、首部裁切偏移与换算后的边界。越界值标为 clamped，边界观测不等于可靠逐字对齐；当前没有把这些时间直接套用到生产字幕。无法放进时窗的候选标为不能交付，不通过截尾或额外变速强行适配。所有样片默认 `awaiting_listening`，播放不会自动登记听辨。

## 已确认问题的交付门禁

```bash
.venv/bin/python video_workflow.py quality-check 'YouTube链接'
.venv/bin/python video_workflow.py release 'YouTube链接'
```

`quality-check` 保存 `delivery_quality.json`。当前有效音频扫描及可核对数据库是必要条件；已确认 `needs_fix` 和历史未复验问题阻断交付。全部跨单元短尾、至少 1.4 秒的句内短尾停顿，必须对当前音频明确 `listened=true` 后 `dismissed/confirmed_correct`；仅写 dismiss 或沿用旧修订的听辨不能放行。其他未知术语候选不一律阻断，高风险也不直接判错。`release` 额外运行真实成品技术验收，前后复查输入与门禁，保存独立 `release.json`；普通 `render` 仍可用于制作待验样片，不等于已 release。

数据库从 v1 增量迁移到 v2，保留扫描和反馈。更改声音、词库或扫描修订不会让历史 `needs_fix` 自动消失；状态区分当前待修与历史待复验。自定义数据库路径记录在工程 `speech_database.json`，状态汇总和交付检查会使用同一数据库，缺失/异常时关闭门禁。

当前修订的问题按原 `speech_review.py review` 命令处理；从 `needs_fix` 改为解除状态必须登记实际听辨和说明。历史声音问题在当前音频上明确复验：

```bash
.venv/bin/python speech_review.py resolve 'YouTube链接' \
  --revision 当前扫描修订 --previous-revision 旧扫描修订 \
  --issue 旧问题编号 --unit 当前复验单元 --listened --note '实际对照与复验理由'
```

`quality-check` 列出的历史文字问题使用其 `problem_id`：

```bash
.venv/bin/python video_workflow.py quality-resolve 'YouTube链接' \
  --problem 旧问题编号 --unit 当前复验单元 --listened --note '实际对照与复验理由'
```

文字复验记录绑定历史反馈内容和当前编译、源片、WAV、成品修订；输入再变更后不能继续沿用。当前文字问题仍应通过当前风险页导入反馈，不能用历史复验接口绕过。任何局部复验都不升级为全片试听完成。
