## 这次真正澄清的地方

1. 1155秒图中，三个8B块合并成24B，但 `malloc(32)` 拆分的是**另一块1048576B空闲块**，剩1048544B。不是从24B里分出32B。中文候选按实际图意恢复这层关系；原始自动英文不改。
2. 1635秒图写键34字节、值64字节，而之后口述示意是32字节。两者没有被擅自统一；也没有把这里的遍历结果当成一般收益。
3. 1900秒图将 `sdallocx` 返回类型印为 `size_t`，但已保存的jemalloc **5.2.1**手册声明为 `void`。四个易混接口分别审查：`nallocx` 只算尺寸、`sallocx` 查询已有分配、`xallocx` 尝试原地调整、`sdallocx` 接受受约束的大小参数。原图和独立AI纠正分开，不冒充讲者已经纠正。
4. `calloc` 保证成功返回的内容按字节为零；共享零页/跳过重复写零是可能的优化，不是允许返回未初始化数据，也不是所有分配都该改为calloc。中文保留原讲中的过强推荐，另列完整AI限定，不能无声替换事实。
5. Linux超额承诺策略、NUMA本地分配可回退其他允许节点、ASan与GWP-ASan的不同定位、对象池不自动解决对象寿命，均另列来源与限制。第212块的否定词仍不确定；正确的系统知识不能证明原声究竟说了什么。
6. 2002年论文是八个应用的比较，不是“定制分配器永远没用”的证明；Mesh保持程序可见虚拟地址，不是任意搬动C++裸指针指向的地址。所有历史测量、当时master、Linux4.18+及“尚不知道公开实现”均不背书2026状态。
